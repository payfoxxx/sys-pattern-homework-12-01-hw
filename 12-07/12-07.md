### Задание 1

Рассмотрим преимущства по отношению друг к другу между master-slave и master-slave (несколько slave)

Преимущества master и один slave:
* Проще управлять, всего два сервера которые необходимо поддерживать;


Преимущества master и несколько slave:
* Более плавное распределение нагрузки на read-операции;
* Если выйдет из строя один slave, то другие будут все равно в работе;
* Более точная настройка для чего будут использоваться разные slave.

### Задание 2

Предположим, какие поля могут иметь наши таблицы:

Таблица пользователи (Users):
|Столбец|Тип|
|--------|------|
|user_id|serial|
|user_name|varchar|
|email|varchar|
|password|varchar|

Таблица книг (Books):
|Столбец|Тип|
|--------|------|
|book_id|serial|
|book_name|varchar|
|description|varchar|


Таблица магазинов (Stores):
|Столбец|Тип|
|--------|------|
|store_id|serial|
|store_name|varchar|


Для таблицы Users будем применять горизонтальное шардирование, разбивая таблицу по user_id

Для таблицы Books вертикальный шардинг:
* book_id, book_name - В одной БД - используется как каталог
* book_id, description - В другой БД - когда подробнее смотрим информацию о книге.

Таким образом, у нас будет одна главная БД, две БД для Users (в одной БД user_id до 5, в другой после 5), и две БД для Books (одна БД для каталога, вторая для описаний).
