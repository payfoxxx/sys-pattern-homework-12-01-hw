### Задание 2

2.1 Для создания SQL-бэкапа в PostgreSQL можно применять утилиту pg_dump:

```bash
pg_dump db_name > dumpfile
```

Данная команда создаст бэкап для базы данных (db_name) в виде sql файла, содержащего запросы - dumpfile.

Для восставновления базы данных, если мы, как было выше, создали sql файл, то применяется команда:

```bash
psql -X db_name < dumpfile
```

db_name - имя БД, в которую будет приосходить восставновление (она не создается автоматически)
dumpfile - файл, из которого происходит восставновление.

Если же у нас имеется архив, или специальный dump-файл, то применяется утилита pg_restore:

```bash
pg_restore [conntection-options] [options] [filename]
```

Данная утилита имеет много настроек, приведем пример для восстановления БД из файла dump, применим опции для создания БД автоматически:

```bash
pg_restore -C -d postgres dumpfile
```

опция -C создаст БД из dumpfile, но нам все равно нужно будет подключиться к какой-то БД для этого, поэтому используем -d postgres (стандартная БД)

### Задание 3

3.1 Для инкрементального резервного копирования необходимо создать полный бэкап командой:

```bash
mysqlbackup --backup-dir=D:\Full_backup backup
```

Затем мы можем запустить инкрементальный бэкап:

```bash
mysqlbackup --incremental --backup-dir=D:\Incremental_backup --incremental-base=last_full_backup backup
```

3.2 Сравнивать резервое копирование и реплики не совсем верно, но попробуем выделить преимущества реплики над резервным копированием:

- реплика может выступить как резервная БД, в случае если с основной что-то произойдет, таким образом не будет простоя;
- реплика также может отдавать данные, тем самым снижая нагрузку с основного сервера БД.
