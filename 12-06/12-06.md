# Домашнее задание к занятию «Репликация и масштабирование. Часть 1» - `Матухно Игорь`

### Задание 1

Главное отличие master-slave от master-master в том, что в подходе master-slave ведущая БД только одна, а master-master не имеет более главное БД, обе могут выступать как главная. Но что у master-slave, что у master-master есть свои недостаткию.

Недостатки master-slave:
* нет ускорения от вставки данных;
* зависимость от master БД (если упадет, то slave не сможет заменить ее без внесения изменений в конфигурацию).

Недостаки master-master:
* могут возникать конфликты при частых вставках данных.

### Задание 2

#### PostgreSQL Docker Compose Master-Slave Replication

* Создаем postgresql.conf для настройки репликации:

```ini
listen_addresses = '*'
wal_level = replica
max_wal_senders = 10
wal_keep_size = 1024MB
max_connections = 100
hot_standby = on
```

* Настраиваем подключения к БД (файл pg_hba.conf):

```ini
# TYPE      DATABASE        USER            ADDRESS                 METHOD
local       all             all                                     trust
host        all             all             127.0.0.1/32            trust
host        all             all             ::1/128                 trust
host        replication     all             0.0.0.0/0               md5
host        all             all             0.0.0.0/0               scram-sha-256
```

* Создаем скрипт для создания пользователя для реплики:

```sql
CREATE USER replicator WITH REPLICATION ENCRYPTED PASSWORD 'replicatorpass';
```

* Dockerfile для master:

```dockerfile
FROM postgres:17

COPY postgresql.conf /etc/postgresql/postgresql.conf
COPY pg_hba.conf /etc/postgresql/pg_hba.conf

COPY init-replicator.sql /docker-entrypoint-initdb.d/

CMD ["postgres", "-c", "config_file=/etc/postgresql/postgresql.conf", "-c", "hba_file=/etc/postgresql/pg_hba.conf"]
```

* Скрипт для инициалазиции слейва:

```sh
#!/bin/bash

PGPASSWORD=$REPLICATION_PASSWORD pg_basebackup -h $MASTER_HOST -U $REPLICATION_USER -p 5432 -D $PGDATA -Fp -Xs -P -R -S slave1 -C
touch $PGDATA/standby.signal
exec /usr/local/bin/docker-entrypoint.sh "$@"
```

* Dockerfile для slave:
```dockerfile
FROM postgres:17

COPY setup-replica.sh /usr/local/bin
RUN chmod +x /usr/local/bin/setup-replica.sh

ENTRYPOINT [ "/usr/local/bin/setup-replica.sh" ]
CMD [ "postgres" ]
```

* compose файл:
```yml
services:
  postgres-master:
    build: ./master
    container_name: postgres-master
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: test_db
    ports:
      - "5434:5432"
    volumes:
      - master_data:/var/lib/postgresql/data
    networks:
      - pg_net
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d test_db"]
      interval: 10s
      timeout: 5s
      retries: 5

  postgres-slave:
    build: ./slave
    container_name: postgres-slave
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: test_db
      MASTER_HOST: postgres-master
      REPLICATION_USER: replicator
      REPLICATION_PASSWORD: replicatorpass
    ports:
      - "5433:5432"
    depends_on:
      postgres-master:
        condition: service_healthy
    volumes:
      - slave_data:/var/lib/postgresql/data
    networks:
      - pg_net

volumes:
  master_data:
  slave_data:

networks:
  pg_net:
    driver: bridge
```

#### Проверяем master-slave:

* На master делаем запрос, и показываем подключенную реплику:

```sql
SELECT client_addr, state, sent_lsn, write_lsn, flush_lsn, replay_lsn, sync_state 
FROM pg_stat_replication;
```

* На slave делаем запрос, true - означает, что это реплика:

